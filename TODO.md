# Milestones

Read SPEC.md, DECISIONS.md, PROGRESS.md and this checklist at the start of each session. For each milestone: investigate one feature/module, implement fresh code, verify, record results, then commit. Add discoveries rather than silently reducing scope.

- [x] M0: locate Avec; staged REA inventory; map observed/candidate features; write spec and decisions.
- [x] M1: typed domain, original demo, persistent store, service bridge and desktop scaffold.
- [x] M2: Home, stack/split reader, mailbox navigation, search, attachments and safe HTML.
- [x] M3: triage, Later todos/bookmarks/dates/reminders, importance/reply status, undo and bulk actions.
- [x] M4: rich compose, recipients/signatures/attachments, replies/forwards, autosaved drafts, popouts, send/undo/failure recovery.
- [x] M5: Groq-only AI summaries/classification, Ask/history/citations, draft proposals and polish.
- [x] M6: Groq voice transcription, microphone choice, voice draft/Ask workflows and cancellation.
- [x] M7: calendar commitments, schedule/event editor, duplicate detection, Google adapter and auto-add preferences.
- [x] M8: account onboarding/switching, Gmail OAuth/sync/search/mutations/attachments/send, secure token persistence and reconnect.
- [x] M9: settings, keyboard shortcuts/native menus, themes/icons/zen, mailto/deep links, notifications and desktop polish.
- [x] M10: focused tests/typecheck/build pass; end-to-end interaction checks; package and launch macOS app; document setup/resume and commit.
- [ ] M11: verify live Gmail connection/sync/send and Google Calendar with Aplos-owned OAuth credentials; verify OS-dependent voice/notifications where granted. Do not claim full parity before this passes.
- [x] M12: close reference signature gap: authorized Gmail sending aliases, per-address imported signatures, reviewed signature choice and MIME sender validation; focused mocked verification.
- [x] M13: close reader fidelity gaps: hydrate externally stored Gmail text/HTML bodies, load CID images on demand outside Spam, and collapse real quoted HTML/history; test and verify the actual reader.
- [x] M14: visual parity with the reference look: hidden title bar with inset traffic lights, native sidebar vibrancy, translucent blurred toolbar, persistent docked Ask panel, 56px rows on rounded cards, floating glass reader dock, inline compose card, pill tabs, matching light/dark palettes; verified side by side in browser and the packaged desktop build.
- [x] M15: native macOS icons: SF Symbols drawn by the OS at runtime through an original helper, with Lucide fallback off macOS; replace interface phrases that matched the reference word for word.
- [x] M16: interaction parity from observed reference behavior: collapsible Ask pill with tap/hold A voice and live matches; stack deck with Done/Todo flings, due prompt and undo return; row hover actions with key hints; inline reply card with Space / hold-to-talk dictation; compose skeleton and fade; grouped menus, split close and floating Reply; tabbed shortcuts; text footer and plain empty states.
- [x] M17: design system and interaction polish: shared tokens and `src/renderer/ui/` primitives (Button, IconButton, Tooltip, Popover, Menu, Dialog/confirm, Toast, Tabs, Select, Checkbox, Switch, Notice, Avatar, Badge, EmptyState, Group rows, Kbd) with consistent motion; every screen migrated off one-off controls; micro-interactions for rows, triage exits, menus, dialogs, toasts, sidebar, composer, settings and calendar; rough spots fixed during preview review.
- [x] M18: UX pass: list keyboard cursor (J/K/arrows, Enter, X, ⌘A, shift-click ranges) with scroll and cursor restored after reading; search field keys, recent searches, data-based hints and highlighted matches; stack position and ⌘F find with count and next/previous; recipient suggestions, invalid-address chips, paste/drop files, pre-send checks and saved feedback; remembered Settings tab, Accounts deep link, debounced signature and auto-listed microphones; calendar duration-preserving edits, inclusive all-day ends, selected-day defaults, double-click and arrow-key navigation, time ranges and guest validation.
- [x] M19: second UX pass: layouts respond to the space left beside the sidebar and Ask (container queries), sidebar opens as an overlay when the window is too narrow, hover actions centered over a full-height fade, Trash/Spam rows restore in one click, Sent and Drafts rows name recipients, Later todos grouped by due date, overdue/due-today times colored, local-date bucketing, snippet-only summaries replaced by a Summarize prompt, Ask matches highlighted and arrow-navigable, block text no longer glued in previews, quieter From options and empty-state wording.
- [x] M20: consistency pass on floating surfaces: one shared material (`--surface-*` tokens, `.ui-surface`, `.ui-surface-item`) for menus, tooltips, toasts, the due prompt, pending send, recipient suggestions and the bulk bar; light toasts with blue text actions; one close button for every dialog; visible menu dividers in dark; matching compose strips; inline replies scroll fully into view; neutral draft-delete wording.
- [x] M21: performance pass: no app-wide re-render every second, on hover or while typing; memoized rows, sidebar, toolbar and Ask with stable handlers; Ask and sidebar slide with transforms (workspace FLIP) instead of animating width; lighter blur; shorter motion; theme and Dock badge applied only when they change. Measured in the packaged app.
- [x] M22: drag to triage: drag a mailbox row or the open stack card left/right with the mouse, touch or a two-finger trackpad swipe; live offset with Done/Todo reveal, tilt, tint and armed state; release past the threshold or flick to commit, otherwise spring back; Escape cancels; the stack fling continues from the drag position toward the configured side.
- [x] M23: drag polish and performance: compositor-only drag updates (own layer, fixed lift shadow, non-inherited registered swipe properties, no per-frame transitions or redundant attribute writes); neutral lifted row that keeps its avatar; release easing that keeps speed; split view lets the card leave before the next email; paused releases are not flicks; pausing a trackpad swipe and carrying on works. Measured in the packaged app.
- [x] M24: local mail engine foundation: SQLite storage behind an engine-owned SQL port (built-in `node:sqlite`, FTS5 search) with one-time import of `state.json`; provider contract (`sync(cursor)`, flag updates, removals); Gmail incremental sync through `history.list` with a bounded first sync and label-only changes applied without refetching bodies; Done/Later kept as Aplos workflow state across syncs; background sync every 60 s and on window focus behind a per-account gate. Tests with a fake Gmail and temporary databases.
- [ ] M25: durable operation queue: triage changes apply locally at once and reach the provider through a persisted queue with retry and backoff (offline-safe, survives restart, sync never reverts a pending change); send hold that cannot double-send after a crash (deterministic Message-ID checked against the provider before any retry).
- [ ] M26: engine extraction: move the service into a platform-free `src/engine` that runs in an Electron utilityProcess, with paged thread queries and change events to the renderer instead of whole-state broadcasts.
- [ ] M27: account setup by address (MX over DNS-over-HTTPS → Google, Microsoft, iCloud or autoconfig) and a DNS checker for custom domains (SPF, DKIM, DMARC).
- [ ] M28+: Microsoft Graph adapter; IMAP/SMTP adapter (iCloud, Yahoo, AOL, generic); JMAP adapter (Fastmail); workflow log synced through a hidden mailbox folder; mobile spike. See the multi-provider plan in DECISIONS.md.

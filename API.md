# Service contract

Renderer calls `bridge.invoke<T>(method, payload)`. Every method rejects with a human-readable Error on failure. Initial/recovery snapshots emit `{type:'state',payload:AppState}`; commits emit `{type:'changes',payload:StateChanges}` with the engine `epoch`, commit `rev`, and only changed rows/fields. Windows resnapshot on a gap or new epoch. Secrets never occur in state/capabilities/errors.

The implementation is `packages/engine/src/legacy/service.ts`: `createEngineService(EngineOptions)` returns `{invoke,subscribe,close}` and receives storage, staged provider memory, provider adapters, Groq, workflow transport, IDs and optional system services through `packages/engine/src/legacy/ports.ts`. `src/main/service.ts` supplies those desktop dependencies through the existing `createService({dataDir,...options})` entry point. The desktop host runs it in an Electron utility process.

- `state.get` `{threadLimit?}` → AppState (a limited snapshot includes `threadCount`); `threads.page` `{before:{date,id},limit?}` → `{epoch,rev,threads,next?}`, ordered by descending date then ID; `capabilities.get` → Capabilities.
- `settings.update` `{patch:Partial<Settings>}`; `account.select` `{id}`; `account.connect` `ConnectRequest` (Google/Microsoft OAuth, IMAP/SMTP credentials or JMAP token; see `packages/engine/src/legacy/provider.ts`); `account.disconnect` `{id}`; `account.discover` `{email}` → provider/server suggestions; `domain.check` `{domain,provider?}` → DNS checks.
- `sync` `{accountId?,auto?}` → state (`auto:true` is a background sync: paced per account, no busy spinner, skipped if one ran recently). Sync first sends queued changes (a manual sync retries failed ones at once); `state.sync.pending` counts changes that have not reached the mail host yet. `demo.reset` → state.
- `thread.update` `{ids:string[],patch:Partial<Thread>}`; `thread.undo` → state; `home.hide` `{ids}`; `search` `{query,accountId?}` → Thread[]. Patch includes status, unread, importance, bookmarked, replyStatus, dueDate, reminderAt, todo.
- `thread.update`, `thread.undo` and `home.hide` accept `compact:true` to return only `{epoch,rev}`. The desktop renderer uses this acknowledgement and follows committed change events, avoiding a whole-mailbox response for triage, read marks, due edits and Undo. Omit the flag for the existing state response.
- `draft.save` `{draft:Draft}` → Draft (autosave/revision); `draft.delete` `{id}`; `draft.send` `{id,resend?}` → state (cancellable delay from settings); `draft.undoSend` `{id}`. Sent demo mail stays local. Provider failure retains the draft and sets `sendError`. A draft gets a stable `messageId` on its first send; `sendAttemptAt` marks a request that may have reached the provider. An unresolved attempt is checked at the provider, never resent automatically; `resend:true` is one explicit Send anyway choice after the UI warns about duplicate delivery.
- Real-account `thread.update`, `thread.undo` and reminders apply locally at once and reach their host through a persisted queue.
- `ai.summarize` `{threadId}` → updated Thread; `ai.polish` `{html,instruction?}` → `{html}`; `ai.draft` `{instruction,threadId?,draft?}` → Partial<Draft>; `ai.ask` `{conversationId?,message,accountId?,requestId?,timeZone?,draft?,context?:{view,threadId?,selectedIds?}}` → Conversation (runs Ask's tool loop; progress arrives as `ai.progress` events `{requestId,type:'text'|'reset'|'step'|'cite'|'usage',…}`); `ai.cancel` `{requestId?}`; `ai.transcribe` `{audio:string,mimeType:string}` → `{text}` (base64 max 25MB). Each runs on the model chosen for its feature in Settings → AI (`summaryModel` for summarize, `draftModel` for polish/draft, `planModel` for calendar extraction, `voiceModel` for transcription, `askModel` for Ask; all `provider:model`, Groq by default).
- `conversation.delete` `{id}`.
- `calendar.list` `{accountId?}` → `{id,name,accountId,primary?,color?}[]` (every account when `accountId` is missing or `'all'`; a host that cannot answer is then skipped, while a single account reports its error); `calendar.extract` `{threadId}` → Partial<CalendarEvent>[]; `calendar.save` `{event:CalendarEvent}` → CalendarEvent (duplicate detection); `calendar.delete` `{id}`.
- `attachment.get` `{threadId,attachmentId}` → Attachment with base64 data; `sender.block` `{email}`; `sender.unblock` `{email}`; `thread.unsubscribe` `{id}` → `{url?:string,message:string}` (safe link, no implicit sending).
- `data.export` → JSON string. Desktop UI can save via native bridge.
- `workflow.status` → `{enabled,available,error?}`; `workflow.enable` `{code?}` → `{code}` (generate a code if omitted); `workflow.code` → `{code}`; `workflow.disable` → `{enabled:false}`. The code stays out of normal app state. Workflow transport uses the host's encrypted app-data records.
- `symbols.render` `{items,scale}` → system-symbol data URLs; a host without native symbols returns an empty map so the renderer uses its vector fallback.

Desktop-only bridge methods handled by electron.ts: `window.compose` `{draftId}`; `window.thread` `{threadId}`; `window.claim` `{draftId}` → boolean; `window.release` `{draftId}`; `window.closeReady`; `window.closeCancel`; `shell.open` `{url}`; `file.save` `{name,data}`; `file.open` `{name,data}`; `notification.test`; `system.login` `{enabled}`; `system.defaultMail`; `system.microphone`; `app.info`. Native close/quit emits `prepare-close`; active compose flushes its latest draft before closeReady, or closeCancel on save failure. Dirty renderer-initiated closes also hold at `beforeunload` and save before closeReady. Without compose, the app acknowledges immediately.

Automatic thread-view read mutations use `thread.update` with `recordUndo:false` so they cannot replace the user's triage undo. `ai.ask` may include a validated current `draft` and `context` (view, open thread, selection); Ask's tools only read or propose, so drafts, events and triage reach the mailbox only through the user's own `draft.save`/`calendar.save`/`thread.update` calls; the original user question is persisted unchanged and proposals are applied only on explicit review.

`src/main/server.ts` runs createService with loopback HTTP POST `/api/invoke` `{method,payload}` → `{result}` or `{error}` and GET `/api/events` SSE. Serve Vite in dev through the same command. Browser renderer uses these two endpoints. Browser-only desktop methods must return clear unsupported messages or sensible web equivalents.

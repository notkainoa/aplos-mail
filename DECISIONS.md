# Decisions

## 2026-10-28 — Test mode: only on data made for the run, never in release builds

- **Release builds compile test mode out.** `scripts/build-main.mjs` defines `__APLOS_TEST_MODE__` as false when `APLOS_RELEASE_BUILD=1` (`release:build`, `release:publish`), so a distributed app ignores `APLOS_TEST` and `APLOS_DATA_DIR` and behaves normally, which is what plan 40's `verify-hardening` checks. Local `npm run package` builds and development runs keep test mode, and agents verify packaged behaviour on those (freeze R2H-4).
- **Only a directory made for the run.** With `APLOS_TEST=1`, `APLOS_DATA_DIR` must exist and resolve (symlinks followed) inside the system temp folder or an explicit `APLOS_TEST_ROOT`. It must not be that folder itself, `/`, home, or the real or preview Aplos data folder. A folder that holds a mailbox key without the `.aplos-test` marker is refused. The marker is written on first start, so a restart of the same run works (freeze R2H-1).

## 2026-10-28 — Revamp Phase 0 artifacts F1-F5 and F7 (freeze candidate)

- **zod/mini, types-only in the engine.** The contract's schemas use `zod/mini` (about 35 KB against full zod's 188 KB in a neutral bundle). The engine core imports contract *types* and the zod-free error classes only; transports validate with `parseArgs` at the host boundary (ARCH 9.3; plan 10 section 3's named fallback), because the runtime schemas plus zod cost about 158 KB of the 400,000-byte budget.
- **Engine budget measured without `legacy/`.** The portability test applies the no-Node rule to all of `packages/engine/src`, but the 400,000-byte check counts only the new engine (UTF-8 bytes, unminified) and forbids new code from importing `legacy/`, which Phase 2 deletes.
- **Contract naming.** Every method is `Type/verb` (`Mail/release`, `Mail/toggleQuotes` rather than `Mail/frame.release`), so the typed client is `api.<type>.<verb>`. Binary moves as `Blob/put` then a `blobId`, never base64. Scopes: `read`, `triage`, `draft`, `send`, `ai`, `admin`, `host`. Submissions add `scheduled`. `conflict` is a reply error type, not a governor error class (adapters return conflicts as results). No key characters (`last4`) leave the engine.
- **Ports (F3)** follow the Providers thread's proposal v2 with the changes listed in STATUS.md (one adapter per account, results for conflicts, only proof makes a send not-sent, one placements list, governor-owned token refresh, `reconnectBy` computed by the host), plus every fix from the Providers review (`packages/engine/src/ports.review-answers.md`): connect ignores auth blocks; per-account monotonic sweep generations with `SweepBound.until` and a `sweep` write in the same commit; the overdue rule applies to queued submissions only, and a submission found `sending` at start becomes `uncertain` and runs `findSent` first.
- **Store (F4).** Schema 0001 is ARCH 3.2 plus the Providers review's S1-S11 and the later additions; `store.commit` is synchronous, data-only and idempotent per required `opId`; `seq` moves once per client-visible commit; `changes` is keyed `(seq, type, id)`; rollups are computed in the store, never taken from a batch.
- **Logger (F7).** The catalog is plain data checked at runtime; its zod schemas are used in tests. Addresses are hashed with a salted synchronous SHA-256 (first 16 hex digits); free text is redacted aggressively and anything over 2,000 characters is replaced whole.
- **UI gaps.** Every gap the UI threads sent is answered in `packages/contract/GAPS.md`.

## 2026-10-27 — Revamp Phase 0 step 1: legacy folders and workspaces

- **Moved, not rewritten.** Today's engine is `packages/engine/src/legacy/` (`@aplos/engine`), the five shared files it needs (`types`, `ask`, `mailbox`, `summary`, `live`) are `packages/contract/src/legacy/` (`@aplos/contract`), and today's renderer is `apps/desktop/src/renderer/legacy/`. All three are read-only reference until Phase 2 deletes them (roadmap 1.1, plan 10 E1 item 1).
- **No re-export stubs in `src/shared`.** The plan allowed one-line stubs so importers compile unchanged. The codemod (`scripts/codemod-imports.mjs`) rewrote every importer to `@aplos/contract/legacy/*` instead, so a stub would have no importer, and leaving a file at the old path would stop git from recording the five moves as renames (`git log --follow` would lose their history). `src/shared/version.ts` stays in the app.
- **`@aplos/engine/legacy/*`, not `@aplos/engine/*`.** Imports of legacy code say so (`@aplos/engine/legacy/discover`), so the new engine's own paths stay free and Phase 2 can find every legacy importer with one search.
- **Internal source packages.** Each package's `exports` maps `./legacy/*` to TypeScript source; there is no build step. tsconfig `paths` and a Vite alias resolve the same files. `scripts/build-main.mjs` bundles `@aplos/*` and keeps every third-party package external (esbuild's `packages:'external'` would have left `@aplos/*` out of the app). `@aplos/*` are dev dependencies of `@aplos/desktop`, so electron-builder never copies their source into `app.asar`; third-party packages they use (today `fast-xml-parser`) stay declared in `apps/desktop/package.json` too, because that is the manifest electron-builder reads.
- **Provider types in the contract.** `AccountPreset`, `ProviderCapabilities`, `ProviderKind` and `ServerSettings` moved to `packages/contract/src/legacy/provider-types.ts`; the engine's `provider.ts` re-exports them. The contract never imports the engine.
- **`appVersion` through `EngineOptions`.** The engine no longer reads the app's `package.json`; the host (`src/main/service.ts`) passes it.
- **Portability test.** It moved to `packages/engine/tests/`, bundles every `.ts` file under `src/` at any depth (instead of one entry file, which nothing provides yet), and has a negative test that plants a `node:fs` import two folders deep. The orchestration run with the Node store, staged memory and Groq stays in the app as `tests/engine-host.test.ts`.
- **Engine size, measured.** The neutral bundle of everything under `packages/engine/src` (all legacy today) is about 353,500 characters unminified (the test's measure; path comments move it by a few hundred) and 201,361 bytes minified, the same as before the move, against the 400,000 budget. MOBILE.md's 146,544 minified figure is from when the engine had 11 modules. The freeze review should decide whether the budget applies to the new engine entry without `legacy/` (which Phase 2 deletes), because legacy plus zod plus new code would not fit.
- **Packaged-app proof without a window.** `scripts/verify-release.mjs` shows the app's window, which the headless rule forbids, so step 1 was proved by `npm run package` plus a content check of `app.asar` instead. The full run waits for F8's hidden test mode (`APLOS_TEST=1`).

## 2026-10-24 — OAuth clients built into releases

- **Closes the open decision on where OAuth client config lives for a public release.** The v0.2.0 draft, installed on a second Mac, could not connect Google: a packaged app read only `~/.config/aplos-mail/.env`, which exists only on the owner's machine.
- **Embedded at build time from repository secrets.** Google's "Desktop app" client type treats the client secret as non-confidential (an installed app cannot keep a secret; Google documents this, and PKCE plus the loopback redirect protect the flow), so bundling it is the standard approach for desktop mail clients. Microsoft's public client has no secret at all. Alternatives rejected: asking each user to create a Cloud project (not workable for a download), and a hosted token-exchange server (an online dependency and a service to run, for no real secrecy gain).
- **How.** `scripts/oauth-defines.mjs` gives esbuild `define` values for `src/main/oauth-config.ts`: the Google client ID and secret and `MICROSOFT_CLIENT_ID`, read from the build environment only when `APLOS_RELEASE_BUILD=1` (`release:build` / `release:publish`). Every other build, `tsx` and the tests inline nothing. Values live only in `dist/main/engine.cjs` in the asar, never in a tracked file or `package.json`; a test checks the repo tree after a placeholder build.
- **Precedence: environment, then built-in, then none.** An ID in `process.env` (dev `.env` or `~/.config/aplos-mail/.env`) wins together with its own secret, so the owner can test another client; the built-in pair is never mixed with an env value. Explicit adapter options (tests, emulator) still win over both.
- **Messages.** Without a client: "Google sign-in isn't available in this build." (Outlook likewise). Development builds add the `.env` hint; release builds don't. The renderer shows the engine's message (`capabilities.get` gained `googleUnavailable` / `microsoftUnavailable`) instead of its own hardcoded copy.
- **Release guard.** On CI a release build without the Google pair fails, unless `APLOS_ALLOW_NO_GOOGLE=1`. Local release builds warn. `MICROSOFT_CLIENT_ID` is optional until Outlook ships.
- **Still open.** Google verification for the restricted Gmail scopes. Until the consent screen is verified, only listed test users can finish sign-in, and Google shows its unverified-app warning.

Neutrals, ink and every app fragment use the app's own tokens, so page and screenshots match. This replaces the green accent and the always-dark site of 2026-10-22.

## 2026-10-23 — Release pipeline and auto-update

- **Artifacts.** electron-builder builds a DMG (what people download) and a ZIP (what electron-updater needs on macOS) for arm64 and x64, plus `latest-mac.yml`. Names have no spaces (`Aplos-Mail-X.Y.Z-arch.ext`), because GitHub rewrites spaces in asset names and the feed would point at files that do not exist. `npm run package` stays the fast this-Mac `dir` build; `npm run release:build` makes the full set. The asar, `extraResources` bin and `extendInfo` are unchanged.
- **Signing.** Hardened runtime with `build/entitlements.mac.plist` (allow-jit, allow-unsigned-executable-memory, disable-library-validation, audio-input), also used for helpers. The Swift symbol helper is now built universal (`lipo` of arm64 and x86_64 slices, macOS 12 minimum) so the Intel build is not shipping an arm64-only binary. It needs no `binaries` entry: electron-builder's signing pass walks the whole bundle, and the test build showed `Contents/Resources/bin/aplos-symbols` signed with the runtime flag like the app.
- **No certificate yet → ad-hoc, not unsigned.** `scripts/release-build.mjs` signs only when `CSC_LINK` (CI) or `CSC_NAME` (local) is set, and otherwise sets `CSC_IDENTITY_AUTO_DISCOVERY=false`, `mac.identity=-` and `notarize=false`. Ad-hoc signing goes a little further than "skip signing": an Apple Silicon app whose seal is broken (Info.plist edited after Electron's own ad-hoc signature) is reported as "damaged" after download, while an ad-hoc app can be opened with Open Anyway. Notarization uses electron-builder's built-in `notarize` with `APPLE_ID` / `APPLE_APP_SPECIFIC_PASSWORD` / `APPLE_TEAM_ID`; a partial set fails the build. Empty GitHub secrets are treated as absent.
- **Updater.** `electron-updater`, GitHub provider (notkainoa/aplos-mail), drafts publish as `releaseType: draft`. `src/main/updates.ts` holds the state machine (idle, checking, current, downloading, ready, error, disabled) with no Electron import, so it is tested with a fake updater. It checks 60 s after launch and every 6 h, downloads silently, and never installs on its own: `autoInstallOnAppQuit` is off, so even quitting does not swap the app. Restart runs the normal quit (drafts saved, engine closed) and only then calls `quitAndInstall`; if the owner cancels a draft prompt, the restart is cancelled too. Later hides the notice for that version until a manual check (menu or Settings) or next launch; the download stays cached.
- **When updates are off.** Development (unless `APLOS_UPDATE_DEV=1` with `dev-app-update.yml`), the browser preview, running from a mounted DMG or App Translocation, and any bundle without a Developer ID Team ID (read with `codesign --display`). Squirrel.Mac only installs an update signed by the same team as the running app, so unsigned and ad-hoc builds would fail at the swap; they say so in Settings → General and in the log instead. electron-updater is loaded only when updates can run.
- **Notice.** A persistent toast ("Aplos X.Y.Z is ready" · Restart · Later) on the existing toast axis. Toasts gained `persistent`, `key` and a quieter `secondary` action; persistent toasts keep their action when newer Undo toasts arrive. Only the main window shows it. No new icon.
- **Version.** One source: `apps/desktop/package.json`, imported through `src/shared/version.ts` (inlined by Vite and esbuild) instead of three hardcoded `0.1.0`s. The root package.json now carries the same version; `scripts/release.mjs` bumps both plus the lockfile, commits, tags and prints the push command. It never pushes.
- **CI.** `ci.yml` uses a `dorny/paths-filter` job so desktop jobs (macOS: typecheck, test, build) run for `apps/desktop/**`, `scripts/**` and shared root files, the website job (Ubuntu: typecheck, build) for `apps/web/**`, and both for root `package*.json`, `packages/**` and the workflow itself. Skipped jobs count as passing for branch protection. `release.yml` runs on `v*` tags, checks the tag matches the app version, tests, then `electron-builder --publish always`. Node 24 to match local development.
- **Google/Microsoft client IDs were runtime-only at first.** Superseded on 2026-10-24: release builds now carry the clients (see "OAuth clients built into releases").
## 2026-10-23 — AI keys in Settings and first-run setup (M40)

- **Where keys live.** Keys typed in Settings → AI go into `ai-keys.enc.json`, a vault file sealed per entry with the same keychain-protected data key (`engine-key.bin`, Electron safeStorage) as account credentials. They are never in app state, `state.json`, SQLite or logs. The engine only ever hands the renderer `{source:'saved'|'environment', last4}`, and `last4` only for keys of 12 characters or more.
- **Precedence: saved, then environment, then none.** A small resolver (`src/main/ai-keys.ts`) is passed to every provider as `apiKey:()=>keys.resolve(id)`; providers read it per request (`readKey` in `llm.ts`), so saving or removing a key works without a restart and `available` is now a getter. Without a resolver, providers still read their environment variable, so `.env`, the eval scripts and `verify-release --live-ai` are unchanged. Claude keeps one SDK client per key.
- **Paste never passes through the renderer.** In the desktop app, Paste is a main-process method (`ai.key.paste`) that reads the clipboard and forwards it straight to the engine's `ai.key.set`. Typing a key into the masked field does pass through the renderer once, at entry; the field is cleared as soon as it saves.
- **Test shows the provider's own words.** `ai.key.test` makes one cheap request: the model list for Groq, OpenAI, Gemini, Claude (one page), Ollama, LM Studio and a custom server; OpenRouter's `/key` (its model list is public); one 1-token completion for OpenCode Go (its model list also needs no key). Unlike every other AI error, a refused key shows the provider's `error.message`, with the key and anything key-shaped redacted, because that is what the owner needs to fix it. Saving runs the test automatically.
- **Errors point at Settings, not `.env`.** "Add your Groq key in Settings → AI to use Groq." and "… rejected the API key. Check it in Settings → AI." The summary card's explanations follow.
- **Browser preview.** No safeStorage there, so the store reports `secure:false` and every key field says keys can only be saved in the desktop app, naming the environment variable to use instead. Saving is refused by the engine with the same message.
- **OAuth client config stays build/environment-time.** `GOOGLE_CLIENT_ID`/`SECRET` and `MICROSOFT_CLIENT_ID` are not user-entered.
- **Welcome flow.** Replaces the single welcome card. Steps: Welcome (Add an account / Look around with demo mail) → the existing add-account dialog → AI (Groq preselected, a provider menu for the keyed providers, the same key field as Settings, a "Get a key" link, Skip for now) → Microphone (hold A / hold Space explained; Allow now via `systemPreferences.askForMediaAccess`, or Later; the status is read with `getMediaAccessStatus` so opening the step never prompts) → Done (Space, A, J K, ?). It runs once per data folder (`settings.onboardingDone`, already persisted) and reopens from Settings → Help & about → Show welcome. The App decides once per load whether to open it, so connecting an account (which the engine already marks as onboarded) doesn't cut the flow short.
- **Escape skips the current step**, and on the first step skips setup; the footer says which. The welcome stays mounted (hidden) under the add-account dialog so focus returns to it instead of the page underneath.
- **Choosing another provider in the welcome.** If the owner saves a key for, say, Claude while Groq has no key, Ask, Summaries, Drafts and Plans that still point at Groq move to that provider's first curated model (and Voice to OpenAI's when it's ChatGPT). Otherwise the defaults stay on Groq.
- **No AI glyph.** The AI step uses a key icon; no sparkle, wand or stars anywhere.

## 2026-10-22 — Monorepo and first website

- **Layout.** npm workspaces, no Turborepo or Nx: `apps/desktop` (the Electron app, moved with `git mv` so history follows), `apps/web` (the website) and `packages/` (reserved, empty). Docs (SPEC, TODO, DECISIONS, PROGRESS, README, API, MOBILE) and `.env.example` stay at the root. Windows and Linux will be extra electron-builder targets inside `apps/desktop`; an iOS app will be another folder under `apps/`.
- **Commands stay at the root.** Root `package.json` has proxy scripts (`npm run <script> -w @aplos/desktop`); `typecheck` and `test` fan out over every workspace. Workspace scripts run with `apps/desktop` as the working directory, so build scripts, vite, tsconfig, electron-builder config and tests needed no path changes. `node scripts/launch.mjs` is a root shim for the real launcher, which resolves paths from its own location. `.env` is read from the working directory and then the repo root (`src/main/env.ts`), so the owner's existing root `.env` keeps working. Existing environment variables still win.
- **Electron is pinned to an exact version** (`44.7.2`). electron-builder cannot read a version range when the package is hoisted to the root `node_modules`, and failed with "Cannot compute electron version"; an exact pin is its documented fix. Bump it by hand.
- **The engine stays in `apps/desktop/src/engine` for now.** It imports five modules from `src/shared` (mostly `types`) and 21 files across main, renderer and shared import it, so extracting it properly means moving `shared` too, rewriting those imports, and making Vite, esbuild and electron-builder bundle a TypeScript workspace package. That is a deep refactor with no second consumer yet. `tests/portability.test.ts` already fails if the engine gains a Node import, so the boundary stays clean. Extract `packages/engine` (and `packages/shared`) when the iOS app starts and needs it.
- **CI path awareness.** No GitHub Actions workflow exists yet. The website is built by Vercel, which skips deploys through `ignoreCommand` in `apps/web/vercel.json` on the same principle. If desktop jobs are added, filter by path: desktop jobs on `apps/desktop/**` plus root `package.json` / `package-lock.json`; website jobs on `apps/web/**`; both on `packages/**`. Docs-only changes run neither. The desktop package job needs macOS runners; the site build runs anywhere.
- **Website stack: Vite + React, multi-page.** Two HTML entries (landing, privacy) build to plain static files; no router and no server. It matches the app's toolchain and adds no new framework to learn or maintain. Astro would ship less JavaScript (the pages are static, and React adds about 70 kB gzipped), but it is a second build system for two pages. Revisit if the site grows or load weight matters. No analytics, cookies or third-party scripts; fonts are the system stack, as in the app. Deployment: Vercel's Git integration (decided 2026-10-23 at the owner's request; Cloudflare Pages was set up first and removed the same day). It gives a preview per PR and a production deploy on merge to `main` with no workflow or secrets in the repo; path filtering lives in `apps/web/vercel.json`. Previews are protected by Vercel login; production is public. Analytics and Speed Insights are off.
- **Website design (revised after owner feedback).** The first pass was clean but plain. The owner asked for the feel of animations.dev, aiforui.dev and Linear's site, and for it to always be dark. Reviewed all three: a near-black ground, big tightly tracked headlines, a framed product window that fades into the page, content that is itself interactive (animations.dev's demo cards), and a restrained tile layout for secondary features. So: dark only (no `prefers-color-scheme` switching, no light screenshots), a soft glow in the icon's green behind the hero window, a sticky translucent bar (the app's own toolbar material), a **working keyboard demo of Home** (`Triage.tsx`: Space, ←, →, Z on the app's original sample mail, with undo and a finished state; keys act only while the demo is focused so the page never hijacks Space or the arrows), a tile layout with real keycaps, provider and account chips, and scroll-in reveals (transform and opacity only, reduced motion keeps opacity only). The taste skill (`design-taste-frontend`, installed at `~/.claude/skills/taste-skill/SKILL.md`; the upstream path only provides that file, so its scripts were not used) was read and its rules were applied by hand in the first pass. Owner rules unchanged: never a sparkle/wand icon, no reference-app branding, the app's own icon and tokens. Emil and Apple guidance shaped the motion: press scale 0.97, ease-out curves, interruptible card exits (each action sends a ghost of the card away while the next one enters, so fast key presses never wait), hover effects gated on real pointers.
- **Screenshots are real.** The app on its original demo data, captured headlessly from its dev server on separate ports with throwaway storage (`apps/web/scripts/capture-screenshots.mjs`). Without an AI key, summaries in the reader and Ask answers are not available, so the site shows the Home focus card (whose one-line summary comes from the demo data), the week calendar and the docked Ask panel with its suggestions, not an answer. No reference-app branding, assets or copy.

## 2026-10-18 — Keep the newest exact inbox copy

- User-requested Aplos behavior, independent of reference research: during incoming sync, compare complete thread content within the same account and archive older exact copies. Match subject, sender/name, To/Cc, full text/HTML/quoted history, sent direction and attachment metadata/bytes; ignore delivery identifiers, timestamps and AI/workflow fields. No AI or network classification is needed for equality.
- Compare whole threads, never just their latest reply, so different conversation history cannot be archived accidentally. Unknown attachment bytes or empty bodies do not prove equality. This does not remove duplicate messages inside a provider-grouped thread; providers currently expose archive operations on whole threads. Only locally downloaded inbox threads are compared.
- Keep the latest delivery timestamp; tied timestamps prefer a newly observed copy, then a stable thread ID within a batch. Handle initial downloads and late/out-of-order batches. Flag-only syncs do not sweep existing mail. Pending local edits and edits made during sync are protected.
- Archive explicitly even when Done is configured as read/unread; preserve read state, bookmarks and todo metadata on the archived copy, which remains in All mail. Save archives and durable provider operations with the incoming mail/cursor/index transaction. Note automatic workflow edits in the same stage. Notify/classify only surviving inbox copies. Do not claim live-provider acceptance from local emulation.

## 2026-10-15 — Multi-provider, serverless architecture

- Researched two open-source mail backends (Redakt, Superlocal) for patterns only; no code copied. Rejected for Aplos: a hosted Postgres/web backend, multi-user tenancy and running our own mail server (Redakt's Stalwart approach): the user's mail host is the sync server.
- Target shape: one platform-free TypeScript engine (`src/engine`) shared by desktop now and a React Native app later; platform specifics enter through small ports (SQL database, secure storage, sockets, OAuth, background scheduling). Providers implement one contract: `sync(cursor)` returning changed threads, flag-only updates, removals and the next cursor; `apply`; `send`; `fetchBody/attachment`; capabilities. Planned adapters: Gmail API, Microsoft Graph (MSAL public client, delta per folder), JMAP (Fastmail), IMAP+SMTP (iCloud, Yahoo, AOL, generic; own threading from Message-ID/References). The engine owns a minimal synchronous SQL port so mobile can use op-sqlite/expo-sqlite later. The existing `state.json` is imported once and kept as `state.json.imported`.
- Aplos-only workflow state (Done vs. merely read, Later, todos, due dates, reminders) is kept locally and survives syncs; the host's labels/folders are authoritative for read, star, trash, spam and inbox membership. A thread returns to Home when a new message arrives, when Gmail moves it back to the inbox while the matching Done/Later action is "archive", or when it lands in Trash/Spam. Cross-device sync of the workflow log goes later through an encrypted hidden mailbox folder (no Aplos server).
- Gmail: the first sync fetches the newest 500 threads instead of the whole mailbox; afterwards `history.list` from the stored `historyId` drives sync. Threads that only changed labels are refreshed with `format=minimal`; added messages trigger a full thread fetch; a missing thread is removed locally; an expired cursor (404) falls back to a fresh bounded sync. Older mail is reached through Gmail search, which is limited to 100 threads per query.
- Background sync runs every 60 s and when a window gains focus, behind a per-account gate (single flight, at least 15 s between automatic syncs, exponential backoff after failures up to 15 min). "Sync now" bypasses the interval but not the single-flight rule.
- Triage is local-first. Each change is applied at once and written, in the same transaction, to an `ops` table as a provider change (remote ID, the status it started from, the patch). A worker sends ops in order per account; one failure holds back only that account's later ops, so a thread never gets an older change after a newer one. Failures retry after 30 s doubling to 15 min; "Sync now" retries at once. A 404 drops the op, since the thread is gone. Sync sends ops before pulling, and threads with an op still queued keep their local status, read, star and labels (new arrivals and removals still apply). Undo and reminders go through the same queue. Disconnecting an account drops its ops.

## 2026-10-16 — M29 workflow sync between devices

- What syncs: each thread's workflow fields (Done/Later/New, reply status, due date, todo, reminder and whether it fired, hidden from Home). Trash and Spam are host state and are not part of it. The log is last-writer-wins per thread (`src/engine/workflow.ts`, platform-free); a merge is commutative, associative and idempotent. Entries are keyed by the host's thread ID (Gmail, Graph, JMAP), or by the thread's root Message-ID for IMAP, whose thread IDs are built per device.
- Only real user edits enter the log (triage, undo, Home hide, fired reminders). Each edit is recorded at edit time as a snapshot of the thread's workflow fields with its edit time and a generation number, in the same transaction as the edit; that edit time, not the sync time, decides conflicts. Mail sync changes (a host archive becoming Done) do not count, or they would override another device's Later. The first device to turn sync on seeds the log from its existing Later, todos, due dates and reminders (timestamped with the thread's last message, so real edits win); a device that joins takes the shared log as it is. Each device remembers which winning entry it applied per thread, so an entry applies once, and an entry for a thread downloaded later (through search, say) still applies when it arrives. A newer message from someone else keeps the thread on Home even if another device marked it Done.
- A round reads every stored copy, merges all of them with this device's edits, writes one new copy and then removes only the copies it read. Two devices writing at once therefore never delete each other's copy; the next round folds both. An edit made while a round is in flight is not acknowledged and its thread is not patched by that round. What a round remembers is saved together with the patches it applies, so a crash in between redoes the round.
- Compaction drops plain entries older than 180 days and records a floor; a merged entry older than another log's floor is rejected, so a long-offline device cannot bring back a Later that was cleared and compacted away.
- Storage: small marked messages in a hidden "Aplos Mail Data" folder per account (a name the user is unlikely to have; a user folder named "Aplos" is ordinary mail). Only messages carrying Aplos's own marker count as records (a header for Gmail and IMAP, a named extended property for Graph, a keyword for JMAP), so user mail is never read or deleted even if it sits in that folder. Gmail uses a label with list and message visibility hidden, `messages.insert`, and trashes replaced copies, because `gmail.modify` cannot delete. Graph uses a hidden folder; IMAP an unsubscribed folder; JMAP an unsubscribed mailbox without a role. Normal sync and search never surface it.
- Encryption: a 28-symbol sync code (130 random bits plus a 2-symbol check, Crockford base32, entered in any case and spacing) → scrypt (N=2^15, random salt per write) → AES-256-GCM with the header authenticated; a separate check value tells a wrong code from damaged data. The code is kept in the credential vault (`workflow-sync.enc.json`), never in app state. Data sealed with a different code or a newer format is reported and never overwritten; damaged data is replaced; a copy too large to open is kept, never replaced, and writes trim old entries until the log fits.
- When: after each account's mail sync, at most every 5 minutes for automatic syncs unless there are edits to share, and on every manual sync. Writes happen only when the merged log differs from the host's copy. Patches from other devices change local state only; the other device already told the host about its own archive or move.

## 2026-10-21 — Ask as a tool-using agent

## 2026-10-28 Google OAuth client secret (providers, #59)

- **A bundled Desktop-client secret is allowed; keys are not.** Google treats the client secret of an installed (Desktop) app as non-confidential, and the token exchange needs it. `oauth/client.ts` may therefore resolve an embedded client id and secret for official builds. This is an exemption from the AGENTS.md "no bundled keys" rule for this one value only; API keys, user tokens and `.env` stay out of the bundle. The secret is never printed or logged.
- **Reconnect always asks for consent.** Google returns a refresh token only on a consent grant, so `reconnectAuthParams` sends `prompt=consent` and `access_type=offline` with the login hint. A reconnect that returns no refresh token is a failed reconnect and keeps the old state.
- **`reconnectBy` carries a margin.** It is the refresh-token expiry less 18 hours (at most half the lifetime), so the weekly reconnect is asked for before the token dies.

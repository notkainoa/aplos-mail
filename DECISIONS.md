# Decisions

## 2026-10-14

- Keep the existing workspace and choose **Aplos Mail** as the original product name; do not copy Avec branding, artwork, fixture mail, code or backend credentials.
- Use REA for behavior evidence. The initial ASAR analysis hit a 20-second deadline; reuse its retained inventory, then inspect individual modules. Native dependency integrity mismatch is a recorded limitation, not ignored evidence.
- Choose Electron + React + TypeScript: matches desktop interaction needs and supports fast visual verification through a local dev server. Use a small explicit service bridge and one persistent JSON store initially rather than a database framework.
- The shell initially lacks GROQ_API_KEY but workspace .env contains it. Load dotenv into the backend environment, ignore it, never display/commit/bundle it. Groq is the only AI provider, including transcription.
- Use original local demo accounts/mail to verify all reversible flows without contacting real recipients. Implement Gmail/Calendar using Aplos-owned OAuth configuration; never borrow Avec's access or identity. Live integration proof remains explicit if credentials are unavailable.
- Reproduce observed production UX and behavior, not internal development galleries/diagnostic APIs or vendor telemetry. Feature-flag candidates require further focused investigation before expanding scope.
- Reference UI inspection is read-only navigation; do not send, delete, triage or unsubscribe reference mail. Keep extracted materials outside the repository.
- Followed REA skill's explicit instruction to decompose independent scopes: separate service, provider adapter and desktop-shell workers; root owns UI and final verification. All share behavior contracts rather than reference implementation.
- Live Groq rejected the older documented Llama model with 404. Verified live model availability and current official deprecation documentation, then chose Groq-hosted `openai/gpt-oss-120b` (override via GROQ_MODEL), plus `whisper-large-v3-turbo` for audio. Both still use only api.groq.com. Synthetic live checks passed for summary/polish/draft/Ask/citations/calendar/transcription.
- Desktop tokens use Electron safeStorage. Browser preview cannot connect/persist Google OAuth tokens; use desktop for connection. GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET are absent, so live Google verification remains open.
- Production launch reads existing environment, optionally augmented from `~/.config/aplos-mail/.env`; development reads ignored workspace `.env`. No env file is included in the app bundle.
- Signature/footer are assembled at delivery from reviewed settings without changing the draft body. AI never changes mail after the Send action; polish remains reviewable before send.
- Browser development uses `Aplos Mail Preview` storage, separate from desktop, to avoid concurrent JSON writers overwriting desktop mail. The small JSON store is suitable for a single personal app service; no claim of database-scale mailbox indexing.
- Keep all-day calendar values as date-only; local calendar display must not interpret them as UTC midnight. Automatic viewing read marks do not enter triage undo history.
- Production dependency audit found vulnerable Nodemailer 7; upgraded to 10.1.1. A broad npm audit fix unexpectedly downgraded electron-builder; restored the known working lockfile. Production dependencies are rechecked separately; dev tooling advisories remain explicit if unresolved.
- Final reference-gap audit added authorized Gmail send-as aliases and per-address signatures. Existing drafts keep their custom-signature choice; new Google drafts use the default authorized alias, or the matching recipient alias for replies. Missing Google settings scope must leave primary-address mail usable with a visible warning.
- Keyboard triage must advance a stack just like its buttons/swipe gestures; split view keeps the current conversation visible. Fixed the inconsistent keyboard path during final acceptance.
- Install this personal app under `~/Applications/Aplos Mail.app`, preserving the reference. For normal Finder launches, populate an absent private `~/.config/aplos-mail/.env` from the supplied runtime Groq environment (0600); do not overwrite existing configuration. The app still reads the key from backend process environment and never bundles it.
- Stop only at the remaining real prerequisite: this app has no Google OAuth client/test mailbox configuration. Do not reuse reference credentials, invent successful live Google acceptance, or mark M11/overall goal complete. Resume files explicitly retain this blocker.
- Gmail body parts stored as attachments are fetched during sync, so search, AI and offline reading see the full text; true files and inline images remain on-demand to keep sync light. Blocked images become text placeholders instead of `src`-less `<img>` elements, so nothing can be fetched and no broken-image icon appears.
- Visual parity (M14) reproduces the reference's measurable look (layout sizes, spacing, radii, palette values, translucency and highlight/shadow recipes) with an original token system and original CSS. No reference stylesheet, icon, image, font file or brand mark is copied; icons come from the existing open-source Lucide set and the app keeps its own name and mark. On macOS the window uses a hidden inset title bar, transparent background and native `sidebar` vibrancy; the browser preview and other platforms use an opaque sidebar color tuned to match the vibrancy sample.
- Ask is a persistent docked panel (open by default, remembered per device) rather than a modal; Escape cancels voice or a pending request instead of closing it. Compose opens as a card over the content column so the toolbar and Ask stay available.
- Icons use Apple's SF Symbols, drawn by macOS at runtime through Aplos's own Swift helper (`native/symbols.swift`, shipped as `Resources/bin/aplos-symbols`) and tinted with CSS masks. No symbol images are bundled; Lucide remains the fallback off macOS or while a symbol loads. Symbol choices are Aplos's own.
- Aplos matches the reference's platform look (system font, SF Symbols, vibrancy, comparable sizes and spacing) but is not an indistinguishable clone: no reference code, styling code, artwork, wording or branding is copied. Interface phrases that matched the reference word for word were rewritten.
- Interaction parity (M16) follows behavior and timing observed in the running reference (open/close durations, fling directions, hold thresholds, menu grouping), implemented with original components, wording and CSS. Hold thresholds: A 220 ms in Ask, Space 300 ms in the reader, Space 250 ms in an empty compose body; a shorter press keeps its tap meaning. Replies open inline in the reader; navigation is blocked while one is open so a draft is never hidden.
- UI is built from one original design system (`src/renderer/ui/`): screens compose primitives instead of styling their own controls, and timing comes from shared duration/easing tokens so motion stays consistent. Destructive actions confirm only when work would be lost (an empty draft is discarded silently). Toasts pause only on real pointer movement, so one that appears under a resting cursor still expires. Floating prompts stack above toasts rather than covering them.
- The list keeps a single keyboard cursor separate from hover and selection; it follows the same visual order as the screen (sections and buckets), so J/K, triage-next and the reader's position agree. Hover moves the cursor only on real pointer movement, so scrolling under a resting pointer does not steal it.
- Pre-send checks confirm rather than block where the user may be right (no subject, mentioned attachment); they block only on things that cannot be sent (no recipients, invalid addresses). Quoted history is ignored when looking for attachment mentions.
- Calendar all-day events keep Google's exclusive end date in storage but show the inclusive last day in the editor. Date math lives in `src/renderer/calendarTime.ts` so it can be tested without the DOM.
- Layout breakpoints for content (split view, calendar, settings) are container queries on the workspace, because the space that matters is what remains after the sidebar and Ask. Window media queries only decide whether the sidebar fits; when it does not, it opens as a temporary overlay instead of vanishing, and the saved sidebar preference is left untouched.
- A thread summary that is contained in the message text is treated as a Gmail snippet, not a summary, and the reader offers to summarize instead of repeating it. Trash and Spam rows show Restore as their only quick action, since Done/Todo do not apply there. Later todos are ordered by urgency (overdue, today, upcoming, undated) using local dates.
- Every floating surface uses one material from shared tokens (`--surface`, `--surface-blur`, `--surface-shadow`, `--surface-radius`, `--surface-inset`, `--item-height`, `--item-radius`, `--item-hover`, `--surface-line`); dialogs use the opaque `--surface-solid` so long forms stay legible. Toasts follow the same light material instead of a dark bar. Native `<select>` stays for pickers so macOS draws its own menu.
- Motion animates only transform and opacity. Panels that change the layout (Ask, sidebar) change size in one step and slide with transforms, with the workspace sliding from its previous position (FLIP), so no animation frame relays out the mail list. Height animation is kept only for the short gap-closing phase of row exits/entries. Frequently changing values (countdown clock, hover, the live draft) live in the component that shows them or in refs, and panes are memoized with stable handlers, so typing or moving the pointer does not re-render the app. Performance is measured in the packaged app, not the preview browser, which uses a software GPU.
- Drag and swipe triage writes its live state to the DOM (CSS variables and `data-swipe*` attributes) instead of React state, so following the pointer costs no renders. Sides map to actions through the Triage direction setting, and every exit (rows, stack fling, arrow keys) uses that same mapping. With a mouse, the reader card only starts a drag outside message text so text selection is not lost; touch and trackpad swipes work anywhere. Content that scrolls sideways scrolls first.
- Gestures animate only on the compositor: the moving element gets its own layer while it moves, nothing painted inside it changes every frame unless it is its own layer too, and per-frame CSS variables are registered as non-inherited so a long email is not restyled on every frame. Values driven every frame never carry transitions; discrete state changes (armed, settle, release) do. Velocity counts toward a flick only if the pointer was still moving when released.

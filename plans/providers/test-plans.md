# Providers thread: test plans for the round-1 lanes

Written 2026-10-27 (day 1) from plan 20's acceptance lists, the roadmap and Brief 2. One table per lane: each test, the layer it runs at, the acceptance item or defect it proves, the exact assertion and the day it should pass. Each lane copies its table into its first PR and keeps it current there.

## In plain English

These are the checks each part of the Gmail and Google Calendar work must pass before anyone calls it done. Most run on practice servers with a fake clock, so an hour of waiting takes milliseconds. A few need a real account. Those run on the spare test Gmail under its rules, or by the owner by hand, and they stay "done pending live check" until then.

Rules applied to every plan below (owner decisions, 2026-10-27). Nothing on the agent test account sends to another address, deletes permanently (including `drafts.delete` and `messages.delete`), empties Trash, unsubscribes, RSVPs, invites attendees or changes settings. Run-scoped drafts reuse one standing scratch draft that is updated in place and never deleted. A run-scoped filter is the one exception the roadmap allows: it is created and removed after the run.

> **What this means:** Every promise in the plans has a named test, and the few that only a real mailbox can prove are marked so nobody mistakes a practice run for the real thing.

### Adversarial checks

A reviewer who has not seen the implementation, with the emulator and only Google's documents, must try to make each of these fail.

- **Retry a send.** Every fault in T24, plus 401 on a send, an actor restart with a submission in `sending`, a double-clicked Retry, and `close()` mid-send.
- **Two requests in flight.** After a concurrency 429, across lanes, and with a zombie actor still holding a request while its replacement starts (T35).
- **Exceed the target in any 60 s window.** Boundary requests, batch parts, clock jumps, and restart loops that reset the log (T41, T42).
- **Retry after quotaExceeded.** Through every path: op flush, workflow round, search, interactive open, calendar, manual sync, wake, restart.
- **Loop on invalid_grant.** More than one token call per attempt, refresh after `needsReauth`, concurrent callers each refreshing, and a wake storm.
- **Send a request during a pause.** Repeated manual syncs, wake storms, restart storms, interactive `thread.open`, and clock set back.
- **Reconnect with the wrong account.** Different sub, same address with different sub, a double-clicked Reconnect, and a kill at each of the six points in T55.
- **Evade the scope manifest.** A scope built by string concatenation, set from env, `include_granted_scopes`, and `https://mail.google.com/`.
- **Hostile classifier input.** `errors[]` with a benign first entry and `quotaExceeded` second, a 10 MB body, HTML 502 pages, text echoing "Rate Limit Exceeded" in a non-error body, and a 403 that is neither of its reasons. It must fail closed to never-retry.
- **Evade the retry lint.** Promise-chain retries, `setInterval`, recursion, and a vendored retry helper.
- **Leak a secret.** Client secret, refresh token or `Authorization` in error text, `providerMessage`, `snapshot()`, diagnostics or a wrong-account token on disk.
- **Lease split-brain.** Both devices primary, a stale lease after clock skew, and a killed holder (T38).

### Spec points to settle before day 5

These are conflicts or gaps in the plans that the tests have to pin. The pinned reading is in the row.

- **Start target.** Governor starts at 4,500 (primary), but `prov-gmail`'s stub and the PV3 first-sync acceptance say 3,000.
- **Lane share base.** ARCH writes "backfill 75% (4,500)", which is 75% of the 6,000 ceiling. The tests read it as share x current target.
- **In-flight cap.** PV0 says one request in flight; ARCH says 3 with 1 reserved.
- **500 threads in "about 3 minutes".** At 40 units per thread that is 20,000 units, or about 4.4 min at 4,500 and 6.7 min at 3,000. It holds only if backfill uses 20-unit `messages.get`. T11 asserts the lower bound and flags this.
- **Retry-After.** Whether it replaces or floors the ladder (pinned: replaces), and whether it advances the step.
- **Quiet-minute counting.** From cooldown end or from the last refusal (pinned: from cooldown end). Regrowth is +250 per minute from minute 10.
- **Transient retry count and jitter.** Pinned as 1 original plus 3 retries, jitter ±25%.
- **Three Macs.** 4,500 + 1,500 + 1,500 = 7,500, which exceeds 6,000 when saturated. The plan's "cannot sum past 6,000" holds only for idle secondaries (T39).
- **`dailyLimitExceeded` scope.** proto-google §3 says every account; ARCH says that budget. T19 pins `quotaExceeded` per account.
- **`sub` source.** Reading it needs a sign-in scope (`openid`) that is not in the four-scope manifest. "Never a broader scope" needs an explicit ruling.
- **Sliding window across restarts** is not persisted in the plan (T41).
- **401 on a send.** Whether the single forced-refresh re-issue applies to a send. T24 assumes no re-issue.
- **Store.** Until `eng-store`'s real commit (day 6), persistence rows run on the in-memory fake store and re-run on the real store.

**Open points the tests pin (resolve with the Integrator before the day 8 tests are written).**
- The plan prices the first window at 40 units per thread (pacing section, `threads.get` metadata) and at 20 (PV3 P1 and "500 threads in about 3 minutes", `messages.get` metadata). T05 and T06 hold the 20-unit reading; with 40, 500 threads takes about 7 minutes at 3,000/min.

### Adversarial checks

A reviewer who has not seen the implementation, with the emulator and Google's own documents, must try to make each of these fail.
- **ADV-01** Retry a send: 429 "Mail sending", 5xx, timeout, 401, abort mid-send, restart mid-send. `messages.send` must appear at most once (T25).
- **ADV-02** Two requests in flight: interactive open during backfill, batch parts, workflow round, search at once. Max in-flight must stay 1 (T02, T03).
- **ADV-03** Exceed 3,000 units in 60 s: random mixes, clock jumps forward and back, the governor swap (T02, T07, T33).
- **ADV-04** Retry after `quotaExceeded` or `dailyLimitExceeded`: restart, wake, manual sync, midnight Pacific edge, the DST-end day 2026-11-01 (T23, T24, T32).
- **ADV-05** Loop on `invalid_grant`: restart, wake and reconnect with the wrong account must make 0 token or API calls until a real reconnect (T26, T62).
- **ADV-06** Send a request during a pause: 100 manual syncs, op flush, workflow round, search and open (T30, T31).
- **ADV-07** Get past a pause with a refusal hidden inside a 200 batch, or with `Retry-After` of 0, negative, past-dated or huge (T18, T21).
- **ADV-08** Falsely delete under a partial scope: drop a history page or batch part during a resync, cap results, fail midway (T47).
- **ADV-09** Ghost hunter: 20 pending history pages, then cursor expiry. Zero ghosts (T46).
- **ADV-10** Replay property: random local ops interleaved with history pages (T49).
- **ADV-11** Independent cost audit from the emulator log (T68).
- **ADV-12** Two-device lease fuzz with clock jumps and killed holders (T57).
- **ADV-13** Content canaries: any subject, address, token or search text reaching a log, error or evidence file (T67).
- **ADV-14** Fidelity probes: an agent given only Google's docs writes 10 "must be refused" requests and runs them against the emulator. Any request accepted is a bug in the emulator, which would make T04-T40 vacuous.
- **ADV-15** A bulk-archive mailbox shaped to defeat the INBOX-gain rule: 400 unknown threads moved into Inbox in one pass, and `labelsAdded` records without `labelIds` (T40, T54).
- **ADV-16** Kill the engine between "token bundle stored" and "queue flushed", and between a page's rows and its token. Nothing lost, nothing sent twice (T14, T61).

### Adversarial checks

A reviewer who has not seen the implementation, given only the code, the emulator and Google's own docs, tries to make each of these fail:

- **A1 Double send.** Get `delivered`=2 through kill points, reset and timeout, a 401 mid-send with token refresh, a governor transient retry with a wrongly tagged `RequestKind`, an undo racing send, two engines (a secondary Mac), and a replay after a pause ends (T03, T26, T27).
- **A2 Lost mail.** Find any path where the mail is not delivered and the submission ends with no state and no message to the user (T27, T28).
- **A3 Stale or foreign draft sent.** Send within the debounce, or with a pending phone edit, and look for a wrong body in Sent (T19).
- **A4 Retry on send-limit or `quotaExceeded`.** Look for more than one request, or a delay before the failure (T23, T25).
- **A5 findSent false negative.** Move the sent mail to Trash, hit index lag, use special Message-ID characters, and look for a "Send anyway" that duplicates (T29 to T31).
- **A6 Draft conflict false positive and negative.** Reorder the response and the history record. Edit remotely during an in-flight save. Delete remotely and look for a dead-id update loop (T10, T11, T13).
- **A7 Foreign recipient on S-self.** Try To, Cc, Bcc, Reply-To, display-name tricks and groups (T54).
- **A8 SSRF.** Try private, mapped, NAT64, numeric-literal, `localhost`, userinfo, rebinding, redirect to a private or `http:` host, a non-443 port, a hostile large or slow response, and a Google token leaking in headers (T43 to T47).
- **A9 Unsubscribe without confirmation.** Call `Unsubscribe/run` from the loopback API, CLI or an AI path without the confirmation field. Also try `mailto:` with injected `cc=`, `bcc=` and CR/LF (T48, T50).
- **A10 Filter damage.** Look for a deleted user filter, a `forward` action, duplicate filters after a crash, or a retry loop at the 1,000 cap (T37, T39, T40).
- **A11 Permanent delete or wider scope.** Grep for delete calls and extra scopes. Check that the emulator's 403 on delete is never reached (T53).

### Adversarial checks

A reviewer who has not seen the implementation, with the fake and Google's documents only, must try to make each of these fail. Each maps to the tests named.

1. No-wipe diff: write any event through every path (title, time, attendees, RSVP, occurrence, series) and diff the server JSON field by field. Any cleared or reset field fails (T28, T29, T43).
2. Ghost hunter: expire one calendar's token with 20 server-side deletions pending and a mid-resync kill. Zero ghost events, and the other calendars make no extra request (T19).
3. Page-token impostor: kill between the last page and the token commit, or store a page token as the sync token (T17).
4. Stale-etag overwrite: another client edits between our read and our write. Any silent overwrite or automatic retry fails (T31).
5. Replay after acceptance: the response is dropped after the server applied the write. A false conflict, a second guest email or a duplicate event fails (T32).
6. Truncated attendees: `attendeesOmitted` and hidden guest lists must never lead to removed guests (T39).
7. Alias self: `self:true` with a different address must patch the right attendee (T39c).
8. Hidden poll: any event request for a hidden or deselected calendar fails (T24).
9. Pause leak: any request during a `gcal` pause or the 3-hour `quotaExceeded` stop, from a focus poll, a manual sync or an edit flush, fails (T22, T41).
10. Quota-reason confusion: `quotaExceeded` retried or treated as throttle, or `rateLimitExceeded` treated as a stop (T21, T22).
11. Single-calendar failure: one bad calendar drops, delays or rolls back the others or the mail commit (T20).
12. Recurrence differential: random rules over ten years in odd zones (Lord_Howe, DST gap and overlap) against both oracles, plus a case where the oracles disagree with each other (T05, T09).
13. Unbounded expansion: `FREQ=SECONDLY`, huge COUNT, a million-year window, `INTERVAL=0` (T11).
14. Unsupported-series rewrite: any edit that resends a `recurrence` Aplos cannot parse (T36).
15. Agent-account guard: try to get the runner to RSVP, add an attendee, set `sendUpdates=all`, delete or touch settings on the agent account (T44).
16. Canary leak: a summary, address or Meet URL in any log, diagnostics or evidence file (T42).
17. Following-split crash, only if Decision 6 enables it: a kill at each of the three points must never leave two series or none (T37).

# Adversarial review of ui-calendar (round 1) — findings
(Paths under apps/desktop/src/renderer/; "model" = screens/calendar/calendar.model.ts.)
LANE-OWNED (fix these):
1a Title-only edit truncates long events (model:721, :751-755): draftFromEvent sets end '23:59' when the end is on another day, draftTimes writes both times on d.date. 22:00 Oct 29→01:00 Oct 30 retitled → end Oct 29 23:59; 36 h event same. Fix: keep an end date in the draft; write `end` only when the user changed it.
1c Editor date change on all-day events (model:1406): only timed events shift their end. One-day all-day Oct 29→Oct 30 refused "An event must end after it starts."; 3-day Oct 27-29 → Oct 28 silently becomes 2 days. Fix: shift end date by the same days.
1d Edit rewrites times from another zone (model:758-759, :777-778): sameTime compares types first; a `floating` NY event title-edited writes start/end back as `utc`; on a series that pins every occurrence. Fix: compare as instants; write times only when changed; keep the event's own time type and zone.
1e New-event time on DST days (model:627): minutes-since-midnight as elapsed time. N at 10:00 suggests 11:00 on 2026-11-01 and 09:00 on 2027-03-14. Fix: getHours()*60+getMinutes() of now.
2 Read-only calendar still allows RSVP (model:364-366, :1087): invite on calendar readOnly:true with can.rsvp:true → Y then Send produces an rsvp effect while Edit says read-only. Decision: trust the engine's `can.rsvp` for RSVP (a read-only calendar can still carry invites you may answer on Google) — BUT make the copy consistent: Edit's refusal sentence must not imply you can't reply; add a test that RSVP follows can.rsvp and edit follows can.edit/readOnly.
3 Toast Undo always undoes the newest change (CalendarContainer.tsx:96, :214, :228-234, :297): every Undo toast uses commandId 'app.undo' → undoStack.undoLast(). Delete A, drag B, click Undo on A's toast → B undone, A's delete still goes out. Same for "Replying Yes to Priya". Fix: each toast gets its own onAction that undoes that write (by opId); Z keeps undoing the newest.
4a Day view: M/N answer an invite nobody opened (model:1042-1062): liveRsvp treats the auto-shown rail as open. Day 2026-10-30, nothing selected → M answers Maybe, N → No. Fix: in Day view the invite counts as open only once the user selected or opened it.
4b Esc can leave Calendar: no Escape command in the calendar context; the model's 'escape' ladder (model:1309) is never dispatched; Esc resolves to nav.back. Fix: attach the model's escape ladder to Esc through the registry if a suitable catalog command/control exists (check renderer/commands catalog + controls); if not, REQUEST ui-foundation for `calendar.escape` and meanwhile handle it in the container with a capture listener that only consumes Esc when the ladder handled it.
4c Arrow keys do two things: with focus on a control (EventDetail answer buttons, MiniMonth), → resolves to calendar.nextPeriod; in the Day rail it changes the day and drops the chosen answer. Fix: don't run calendar arrow bindings when focus is inside a control that handles arrows (mark those regions; check how the registry's context stack / data-keyctx works), or REQUEST.
4d Narrow pane switcher out of step (model:85-87, CalendarScreen.tsx:259): under 720 px with Day/Month chosen, the switcher still shows Day/Month while the label reads a week and J moves a week. Fix: when the agenda shows, label the period consistently and reflect it in the switcher (disable it or show the agenda state) — consistent with DESIGN 7.8 "Narrow: an agenda list".
PLAUSIBLE (lane side, fix or guard with a test): "All events" on a move/edit sends this occurrence's new times (model:1131-1135) — for scope series, send a time *delta* or the series' own start shifted by the same offset, not the occurrence's absolute times (state your reading in a comment and raise CONTRACT question in your report); undo racing the write (undo pressed before Event/set returns must cancel once the opId arrives, never be lost); two undo entries per write if the data layer also adds one (ensure the lane adds its own entry only when the port doesn't); Return handled twice (grid Enter + registry calendar.open) — make sure only one acts; an event crossing midnight isn't drawn on its second day so N there treats 00:00-01:00 as free (fix the free-slot computation to use real events).
UI-FOUNDATION (do NOT edit renderer/ui; list as REQUESTs, add test.todo with [waits: ui-foundation]): 1b drag length from the clamped day segment (ui/calendar/layout.ts:57 + TimeGrid drag) shortens a midnight-crossing event; 1f zero-minute events pile up with no +N (layout.ts:115); 1g day view never shows +N for 3-5 overlaps (layout.ts:40 day cap 6) — DECIDED: DESIGN 7.8 wins over the mockup, 3+ overlapping events show the first lane plus "+N" in the day view too; 6 choosing an answer moves neighbours 0.85 px (ui/calendar/calendar.css:1174-1179, font-weight on content-sized buttons).
